# 装机测试清单（libvlcrs VR 播放器 · arm64-v8a）

面向实机验收。每一条都给出**操作**与**期望结果**，最后留空给你填 ✔/✘ 和现象。
被测对象：`libvlcrs-vr-demo-1.0.0-arm64-v8a.apk`（release，仅 arm64-v8a）。

---

## 0. 装机前置

| 项 | 要求 |
|---|---|
| ABI | `arm64-v8a`（APK 只含这一种，装到 armeabi-v7a/x86 设备会失败） |
| Android | 8.0 (API 26) 及以上（引擎使用 AAudio 与包级 SensorManager） |
| 传感器 | 陀螺仪 + 加速度计（仅"陀螺仪环视"用例需要） |
| 签名 | CI 生成的 debug key。**安装前先卸载旧版本**，否则会 `INSTALL_FAILED_UPDATE_INCOMPATIBLE` |

```bash
adb uninstall org.videolan.libvlcrs.demo 2>/dev/null
adb install -r libvlcrs-vr-demo-1.0.0-arm64-v8a.apk
adb logcat -c && adb logcat -s libvlcrs:V AndroidRuntime:E > vlcrs.log   # 另开一个终端抓日志
```

启动后首页顶部会显示引擎版本、设备 ABI/API 与"是否支持"。**若显示 ⚠ 不支持，请记录设备型号并停止后续测试。**

内置自测片源（首页列表，均由 CI 用 ffmpeg 生成并写入真实球面元数据）：

| 文件 | 几何 | 元数据 | Auto 应解析为 |
|---|---|---|---|
| `planar_16x9.mp4` | 16:9 普通视频 | 无 | **Planar 2D**（fallback） |
| `vr360_mono.mp4` | 2:1 | st3d=mono + sv3d/equi | **360° mono**（metadata） |
| `vr360_sbs.mp4` | 2:1，左眼=动态测试图、右眼=彩条 | st3d=left-right | **360° SBS** |
| `vr360_tb.mp4` | 2:1，上半=动态测试图、下半=彩条 | st3d=top-bottom | **360° TB** |
| `vr180_mono.mp4` | 1:1 | equi 带 25% 左右裁切 | **180° mono** |
| `vr180_sbs.mp4` | 2:1 SBS | equi 带 25% 左右裁切 | **180° SBS** |
| `vr360_mono.mkv` | 2:1 Matroska | Projection/ProjectionType=1 | **360° mono**（EBML 路径） |

所有片源都带 440Hz(左)/880Hz(右) 正弦音轨，用于同时验证音频链路与下混。

## 3. 180° 边界收敛（需求 3 的关键项）

| # | 操作 | 期望 | 结果 |
|---|---|---|---|
| 3.1 | 180 片源，Gyro=off，持续向右拖拽 | 偏航到 `+(90−FOVx/2)` 附近后**逐渐变"重"**（阻尼感），HUD 出现 `YAW LIMIT`，画面右边缘贴住画面边界 | |
| 3.2 | 继续拖拽不松手 | **任何时刻都不出现黑边/黑块**（边界外是画面边缘像素的延展，不是黑色） | |
| 3.3 | 反向拖回 | 立即恢复 1:1 跟随，无"粘滞"或需要拖很远才响应 | |
| 3.4 | 拖到底后双指放大（FOV 变小） | 边界随之放宽（`90−FOV/2` 变大），可继续向该方向看更多 | |
| 3.5 | Gyro=on，转身超过 90° | 允许更宽（可到覆盖边界），极端角度可能出现边缘延展；**这是需求允许的放宽** | |
| 3.6 | 上下俯仰到底 | 同样收敛，HUD 出现 `PITCH LIMIT`，不出现黑区 | |

## 8. 需要回传的信息（若某项 ✘）

1. 设备型号 / Android 版本 / ABI：
   `adb shell getprop ro.product.model; adb shell getprop ro.build.version.release; adb shell getprop ro.product.cpu.abi`
2. 完整日志：`adb logcat -d -s libvlcrs:V AndroidRuntime:E > vlcrs.log`
   （引擎所有关键路径都会打日志：`probe:`、`prepared:`、`video decoder started`、`projection:`、`uploaded … mesh`、`EGL window surface …`、错误与 `GL error`）
3. 出问题的用例编号、片源名、当时的 Mode/Eye/Gyro 设置与 HUD 截图。
4. 若是画面异常（黑屏/花屏/比例错/上下颠倒），请特别说明：**黑屏**还是**画面错位**，以及切到 `Planar` 是否正常（可快速区分是投影问题还是解码/纹理问题）。

## 9. 已知限制（不作为缺陷）

* 仅 `arm64-v8a`、API 26+。
* 解复用/解码全部走系统 `MediaExtractor`/`MediaCodec`：设备支持的容器与编码才能播；不内置任何编解码器（这正是 .so 只有 ~0.7MB 的原因）。
* Cubemap / mesh 投影会被识别并上报 `UNSUPPORTED_PROJECTION`，但不渲染（只支持等距柱状 360°/180° 与平面 2D）。
* 无字幕、无多音轨切换、无倍速、无投屏。
* 180° 片源在**极端俯仰**（接近天顶/地面）时，因经度在极点附近压缩，边界外会出现"边缘像素延展"而非黑块——这是刻意的兜底策略。
* APK 用 CI 生成的 debug key 签名，仅供测试。
